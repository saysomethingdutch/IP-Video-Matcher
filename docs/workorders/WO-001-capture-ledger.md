## 1. 目标

对一次公证取证的全部录像，为**原告表格的每一行**自动产出一条台账。台账包含：
- 该行视频在录像里的位置
- 视频时长
- 取证时长（按被诉视频自身时间计算，已还原倍速）
- 是否完整播放、跳播区间、倍速
- 播放量读数、分P/合集读数
- 证据截图

另外，每条录像生成一个 HTML 核对页，目标是**人核对一行不超过 1 分钟**。

## 3. 技术要求（能简单就简单）

### 3.1 OCR
- 引擎：**macOS Vision**
  - `VNRecognizeTextRequest`，语言设为 `["zh-Hans","en-US"]`
  - `recognitionLevel = .accurate`，`usesLanguageCorrection = false`
- 实现：写一个 Swift 小程序 `pilot/tools/ocr_vision.swift`，编译到 `pilot/bin/`。批量读图，输出 JSONL，每帧一行：`{"frame": ..., "items": [{"text", "conf", "x", "y", "w", "h"}]}`，bbox 用归一化坐标，原点在左上。参考审计附录 A 的代码。
- 不要引入需要下载模型的 OCR（例如 PaddleOCR）。所有者的网络是手机热点。
- 4 进程并行。结果按 `(录像文件名+大小, 帧时间)` 缓存，重跑时不重复计算。

### 3.2 抽帧与磁盘
- 用 ffmpeg，默认 1 fps（可以配置成 2 fps）。帧时间由输出序号换算，报告中注明误差不超过 0.5 秒。
- 不需要做 PTS 比特级校验。
- **内置磁盘只剩约 19 GB**：抽出的帧 OCR 完就删掉。只保留台账引用到的证据帧，缩到宽 640px 的 JPEG。

### 3.3 远景录像
- 支持在 `pilot/cases/*.yaml` 里为每条录像（可以按时间段分）手工给一个裁剪框 `crop: [x,y,w,h]` 和放大倍数 `scale`（默认不裁剪）。流程是先裁剪放大，再 OCR。
- 人工框一次是允许的（D-002）。
- 用 MAH00002 分别报告"不裁剪"和"裁剪放大"两种条件下的结果。

### 3.4 页面解析（规则即可）
- 页面类型分四类：横屏播放器、竖屏详情页（上面有小窗播放器）、搜索结果页、其他。
- 需要抽取的字段：
  - **播放器读数**，形如 `00:34/13:13`。正则要容忍 OCR 误读：`:` 可能被读成 `;`，`/` 可能被读成 `7`。
  - **倍速**：0.5X/0.75X/1.0X/1.25X/1.5X/2.0X。倍速菜单打开时画面上会同时出现多档，要能识别并忽略。
  - **标题、UP 主名、BV 号**。BV 号 = `BV1` 加 9 位 base58（字母表里没有 0、O、I、l）。做确定性纠错：`I`/`l` 改为 `1`，首位 `8V` 改为 `BV`。最终以闭集匹配为准，见 3.5。
  - **播放量、发布日期、分P/合集标签**，例如"合集 5/27"、"04-1"、"P3"。
  - **手机状态栏时钟**，例如 `13:44`、`下午1:43`。

### 3.5 关联到表格行（闭集匹配）
- 只在这批表格行中找最接近的，不做开放识别。
- 优先级：
  1. BV 号：编辑距离 ≤2 且唯一
  2. 标题前缀模糊匹配加 UP 主
  3. 播放器总长等于表格时长（±2 秒）
- 每个关联都要输出依据和置信度。

### 3.6 截图
- 对截图做 OCR，并从文件名解析出时间。
- 用录像帧里的状态栏时钟，把截图对齐到录像时间轴，分钟级精度即可。
- 截图里的 BV、标题、播放量、分P 信息，作为对应会话的高置信证据。

### 3.7 会话与 PlaybackMap
- **会话** = 录像中同一条被诉视频的连续区间。中间可以夹详情页、竖屏小窗、UI 隐藏的时段。
- 在会话内，用播放器读数拟合"录像时间 → 被诉视频时间"的分段线性映射，斜率约等于倍速。
- 需要检测三种事件：
  - **跳转**：跳变超过 4 秒，且与倍速不符
  - **暂停**
  - **回放**
- UI 隐藏期间按倍速外推，但标记为"推定"。
- 计算以下字段，口径以《七时吉祥比对要求》为准：
  - `视频时长`：读数里的总长
  - `取证时长`：已播放的被诉时间区间之和。倍速且从头播到尾，等于视频时长；拖曳时，等于实际播放长度；倍速加拖曳，一律按被诉视频自身时间计
  - `是否完整播放`：从约 0 秒播到约结尾，且没有超过 3 秒的跳过
  - `跳播区间`、`最大播放位置`、`倍速`

### 3.8 输出（放在 `workspace/pilot/<case_id>/`）
1. `ledger.jsonl`：每个表格行一条。每个字段都带来源信息：录像文件、录像时间点、证据帧路径，以及来源类型（OCR 读数 / 截图 / 推定）。
2. `ledger.csv`：给人看的版本，一行一条。
3. `unmatched_sessions.csv`（找到了会话但没关联上任何行）和 `rows_without_session.csv`（表格行没找到会话）。
4. 每条录像一个 HTML：
   - 时间轴，用色块标出各个会话
   - 每行的关键帧：开始、首个读数、每次跳转的前后、结束
   - 读数表、计算结果、问题标记
5. `run_summary.json`：耗时、帧数、关联率、各类标记的计数。
