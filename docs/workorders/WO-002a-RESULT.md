# WO-002a 交付说明：原剧台词字幕索引

分支 `pilot/wo-002a-textindex`，代码在 `pilot/textindex/`，只用标准库。产物在 `workspace/pilot/textindex/qsjx/`：`index.sqlite`、`stats.json`、`ocr/EPxx.jsonl.gz`（逐帧 OCR 缓存）。加新集时只 OCR 新集；改合并规则时从缓存重算，不需要重跑 OCR。

## 1. 命令（在仓库根目录执行）

```bash
/opt/homebrew/bin/python3 -m pilot.textindex build --episodes real_test --work qsjx      # 增量构建
/opt/homebrew/bin/python3 -m pilot.textindex query --work qsjx "现在要怎么办呀"
/opt/homebrew/bin/python3 -m pilot.textindex match --work qsjx pilot/textindex/tests/data/positive1.tsv  # --json 输出 SourceLink
.venv/bin/python -m pytest -q pilot/textindex/tests                                      # 23 个测试，含 §4 回归
```

Python 接口是 `Index.load(db)` 加 `match_sequence(index, [(t, text), ...])`。每行返回 LINKED / AMBIGUOUS / NO_MATCH，并附集数、原剧时间、相似度和置信度。

## 2. stats.json 摘要

- 规模：32 集（缺 20、21、22、26、29、34），163,101 帧，18,987 条台词，每集 374–731 条。
- 标记比例（全部条目 / 只算 ≥4 字）：OPENING_ENDING 14.2% / 2.3%，RECAP 10.0% / 3.0%，BOUNDARY_REGION 0.8% / 0.8%，SHORT 22.4%，带任一标记 26.2% / 4.8%。
- 多集重复：去重后 15,562 句，6.0% 出现在 2 集以上；只算 ≥4 字是 3.4%。
- 耗时（4 个 OCR 进程）：首批 14 集 918 s（15.3 分钟），满足 ≤20 分钟，当时机器上还有别的负载。新增 18 集的增量构建 949 s，平均每集 53 s。没有新集时重跑只需 0.1 s。

## 4. 需要 Owner 决定的问题

1. **正例 2 的 EP03 终点**：样例最后一句"不都得给她挥霍干净了"在 2255.5 s。工单写的 2273 s 是下一句"我是真的没有想到"，这句不在样例里，也出现在 EP04 137.5 s 的前情里。我按"落在 2169–2273 内且单调"验收，请确认。
2. **边界文件**：`experiments/phase3a0/cases/source_boundaries.json` 已不在工作区，只存在于 `archive/phase3` 分支。文件里 14 集的数值与保守规则 [140 s, 时长−200 s] 完全一致，所以代码内置了这条规则，32 集统一使用。后面几集的正片可能更早开始，例如 EP23 在 108 s 就有台词；这只影响 BOUNDARY_REGION 降权。需要逐集边界吗？
3. **前情提要**：每集开头约 130–160 s 会重放上一集最后 20–30 s，两处都标 RECAP。有上下文时，链会选前后连贯的那一处；孤立的单句判为 AMBIGUOUS，并列出两处。要不要只给后一集的副本降权？另外，缺集的结尾台词只出现在下一集的前情里，而且不带 RECAP，会被链接到下一集开头；补齐缺集后重跑 build 即可。
4. **与工单字面的细节差异，请确认**：编辑距离 ≤1 的合并只用于两边都 ≥3 字的句子，避免把"怎么"和"什么"并成一句，并允许中间漏检 1 帧；归一化另做了 NFKC 和英文小写；相似度用 LCS 比值（与 rapidfuzz `fuzz.ratio` 相同），没有用 difflib；OPENING_ENDING / SHORT 按整行降权，RECAP / BOUNDARY_REGION 按候选降权，这样高频短句的精确匹配不会输给别的句子的部分匹配。
