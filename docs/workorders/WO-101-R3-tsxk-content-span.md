## 为什么要做

视频播完后，B 站会显示满屏推荐，或者从头重播。这些帧仍在目标页面的区间里，被时间线当成了视频内容。
- 8325、8516 的"偷渡"，8452 的"剧场版"，都来自这种帧。
- 8528 开头是 B 站报错页，真正的播放从 114 秒才开始。

目标页面区间（`play_start`、`play_end`）照旧保留。另外要给出**实际播放的起止**，时间线和分类只看这一段。

## 1. 新增结构化字段

- `passes`：进度条的每一遍，逐遍记录：录屏起止秒；起止进度；是否完整；是否外推。
- `content_start`、`content_end`：实际播放区间，用录屏秒表示。
  - 有完整一遍的，取第一遍完整的起止；
  - 没有完整一遍的，取实际看到在播放的起止。
- `content_basis`：写明依据，例如"进度条第 1 遍完整""进度条外推""进度条量不到，退回页面区间"。
- `complete_needs_review`：R 靠外推、而且实测最高进度不到 90% 的，填 true；页面何时结束拿不准的，也填 true。现在"是"里有 8 行属于前一种（7824、7826、7832、7919、7988、7998、8008、8103）。Claude Code 会把它们标黄。

## 2. 页面结束的判断

- 地址栏的 BV 被 OCR 读进了别的字，也要认出来。例子：7844 把 `BV1nLz9BJEiX` 读成了 `BV1nLz9BJE议X`，台账就以为浏览器关了，把一条完整播完的 13 秒视频判成了"否"。
  - 办法：容许 BV 里夹杂 1–2 个非字母数字的字符；标签页标题和目标页面相同的，也算仍在目标页。
- "浏览器关闭"要有正面证据，比如看到 Windows 桌面，不能只凭"没读到网址"。
- 地址里带 `player.switch` 的（合集或分P自动切到下一条），和 `player_end_recommend_autoplay` 一样，都是"上一条播完了"的旁证。
- 页面上出现 B 站报错页的（例如 8528 开头），在 flags 里记下；`content_start` 以进度条开始走动为准。
