- 背景：DECISIONS D-061 ②。进度条的量法没问题，问题出在怎么从读数判出 R。

## 1. 剔除读数毛刺

- 画面里的蓝色特效，会让个别帧的读数突然跳高，下一帧又回到原来的走势。这是毛刺，不是跳转，要剔除。
- 连续两点以上都停在新的位置，才算跳转。
- 例子：8029、8050、8071，进度条其实都走到了 100%。

## 2. 按"遍"判断

- 读数从高处落回 0 附近，说明重播或连播开始了，就从这里切开，每一遍单独判断。
- 任何一遍从头播到尾、中间没有跳转，R 就判"是"。
- 例子：7928 在 380 秒走到 100%，382 秒落回 1%，应当判"是"。

## 3. 起止允许外推

- 用每一遍的走势，外推它的起点和终点。
- 外推的起点落在目标页面出现之后，外推的终点落在目标页面结束之前，就算从头播到了尾。两头各留几秒余量。
- 依据字段里写明"外推"。
- 例子：8189 从 4.6% 走到 99.8%，8014 从 0.9% 走到 98.4%，7982 从 14.6% 走到 100%，都应当能判出来。

## 4. 判"否"的要附证据

- 每一行判"否"的，保存两帧截图：跳转处的前后两帧，或者结束处的那一帧。
- 列成清单，交 Owner 抽查。
