失败的原因有三个：
1. **用 JSON schema 强制约束输出**：ollama 的 `format` 按字母序先生成 `evidence_frames`、`form_guess`，模型还没"看"，就被迫先选了枚举值。
2. **没有裁剪**：整张 1280×720 画面里有一半是桌面和手机边框。
3. **一次传 4 张图**：量化模型对多图输入的处理不稳定。

另外，MiniCPM-V 4.6（1.3B）在自由文本下会自相矛盾，例如"整屏电视剧"和"真人出镜加小窗"同时出现。**不再测 4.6。**

## 1. 新的测试方法

1. **裁剪。** 输入只保留手机屏幕区域。近景录像（MVI）可以按录像给固定框，也可以用 WO-001 台账里横屏播放器的 UI 位置自动推出，放大到宽约 1280。
2. **单图。** 每行 4 帧拼成一张 2×2 拼图，一次调用。
3. **两步。**
   - 第一步：视觉模型用自由文本描述，不超过 150 字，不加 `format` 约束。提示词参考下面的附录。
   - 第二步：只用文本，把描述映射成原来的 JSON 字段。用本机已有的 `qwen3:4b-instruct`，或同一模型的纯文本调用都可以。允许"不确定"。描述里前后矛盾时，这个字段写"不确定"，并标记"描述自相矛盾"。
4. **几何字段不交给视觉模型。**
   - `rights_content_ratio` 和"原剧缩小加背景或边框"由几何方法计算：在屏幕裁剪区域内，对这一行会话的多帧求逐像素时间方差，变化剧烈的矩形就是原剧画面，静止的部分是装饰或背景。算出它占视频画面的面积比，吸附到 {1, 4/5, 2/3, 1/2, 1/4}。
   - 视觉模型的这两个字段只作参考，一并输出。
5. **模型。** 主测 Qwen3-VL-8B，对照 MiniCPM-V 4.5。
