## 3. 要求

### 3.1 RowDigest

### 3.2 非分类列（确定性规则，不用大模型）

| 列 | 规则 |
|---|---|
| 视频时长、取证时长 | hh:mm:ss；"未知"就写"未知" |
| 是否完整播放 | 取台账结论 |
| 合集/分P | 取台账读数，读不到写"未识别" |
| 播放量是否正确 | OCR 读数与表格对比，写"是"，或"否，X"，或"无，X" |
| 对应集数是否正确 | 见下 |
| 非权利作品 | 真人出镜、其他作品来自画面事实；背景音乐以歌词字幕轨作为线索。能列出具体是什么就列出来，**但不写商单广告** |
| 遮挡物 | UP 主字幕、花字来自字幕轨；贴纸、边框来自画面事实。**不写 UP 主水印和 B 站水印** |
| 画面大小 | 几何比例与画面模型一致时采用；两者不一致，加标记 |

**对应集数是否正确**按 content 的结论填写：
- `SUPPORTED`：写"是"。
- `NARROWER`：写"否，已取证部分对应第X集（原告声称Y）"，标黄，由所有者决定措辞。
- `CONTRADICTED`：写"否，第X集"，标黄。
- `UNVERIFIED`：写"是（未能核实）"，标黄；有 `TITLE_EPISODE` 的附上参考。

所有"标黄"都写进 `flags`，核对页上要醒目显示。

**分P 与重复取证**（2026-09-25 补充，Owner 已更正。依据客户要求"合集与分P""多次取证的情况"两节）：

- **同 BV 不等于重复。** 本批同 BV 的行大多是**分P**，标题末尾是"1/2""2/2"，例如 1051/1052、1053/1054。
  - 它们是同一稿的不同段，各自正常比对。
  - V 列写"分P"，W 列写"共2P，取证了第1P"这种格式。
- **真正的重复取证 = 同 BV 且同一 P。** 本批内只有 1116，它与 1114 同为 BV1W94y1p7Ea 的第 2P。
  - 取播放更完整的一次作为主行，正常比对。
  - 另一行按原表已有写法，U–AJ 全部写 `同序号XXXX，重复取证`，XXXX 为主行的总编号（参照 1204、1218）。
  - 主行的播放量取**最后一次**取证的读数。
- **与本批以外的行重复：**

### 3.3 性质分类（大模型，**看不到目标**）

- 输入只给 RowDigest 里的事实：UP 主文字、画面事实、原剧台词句数和位置、是否跳播、视频标题。
- **不要给原告的"视频类型"**，它不可信。本案人工表里：
  - 原告标"切条"的 239 行中，93 行被判为混剪类（合理使用），61 行为否/否；
  - 原告标"原片"的行里，有 33 行被判为跳播 + reaction。
- **禁止出现**"本案以论证合理使用为目标""辩护""被告"这类字样。
- 输出结构化 JSON，只能从下列取值中选：
  - `观点评析`（带子类：深度解读、拉片解读、细节分析、人物小传、服化道盘点、文化科普、恶搞讽刺）

### 3.4 客户口径规则（`pilot/semantic/rules_qsjx.yaml`，每案可替换）

| 性质 | 合理使用可能性 / 演绎可能性 / 合理使用类型 / 演绎类型 |

| 夹叙夹议解说 | 是 / 是 / 夹叙夹议类解说 / 夹叙夹议解说 |
