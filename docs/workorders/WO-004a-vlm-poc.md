# WO-004a 本地视觉模型 POC（关键帧 → 结构化画面事实）

- 分支：`pilot/wo-004a-vlm`　代码目录：`pilot/vlm/`　输出目录：`workspace/pilot/vlm/`
- 交付说明：`docs/workorders/WO-004a-RESULT.md`，不超过 1 页

## 0. 目的与边界

本地视觉模型只负责把"已经定位好的会话画面"转成表格需要的**画面事实**。它**不负责**：时长、跳播、倍速、BV 号（这些由 OCR 和规则得出，见 WO-001），集数、原剧时间点（由台词索引得出，见 WO-002a/003），像素级身份比对，也不做任何法律判断。

本 POC 只回答一个问题：哪个本地模型在这些字段上准确、稳定、够快。

## 1. 候选模型（都用 ollama 本地跑，已安装在 `/opt/homebrew/bin/ollama`）

1. **MiniCPM-V 4.5**，8B，Q4 量化，约 6 GB。当前 Hugging Face 模型卡标注为 Apache-2.0，登记问卷自愿填写。
2. **Qwen3-VL-8B-Instruct**，Q4 量化，Apache-2.0，官方提供 GGUF。
3. 可选：**MiniCPM-V 4.6**，1.3B。只在 ollama 里能直接拉到时才测，作为"快而小"的对照。

注意事项：
- 内置盘约有 52 GB 空闲，最多下载 3 个模型。
- 模型的准确 tag 以 ollama 官方库为准，在交付说明里写明实际用了哪个 tag。
- 不用任何云端 API，不做微调。

## 2. 输入

**样本：** 七时吉祥证据18 中 WO-001 已高置信关联的行，取 20 行，按原告"视频类型"分层：Reaction、切条、解说、原片各 5 行。每类按总编号升序取前 5 个高置信行。**选择规则写进代码**，不要手挑。

**关键帧：**
- 每行从录像原片（1280×720）里取 4 帧。条件是"正在播放、UI 隐藏"的时刻，尽量分布在会话的前、中、后段，避开拖动进度条的那几秒。
- 录像在外置盘 `/Volumes/Element/...`。如果外置盘没挂载，就停下来，在交付说明里写明原因。
- **不给模型看标题。** 本 POC 只测视觉理解。

## 3. 字段（严格 JSON，中文枚举，允许"不确定"）

```json
{
  "layout": "全屏|原剧缩小加背景或边框|画中画(原剧为主)|画中画(UP主为主)|竖屏裁切|不确定",
  "rights_content_ratio": "约1|约4/5|约2/3|约1/2|约1/4|其他|不确定",
  "uploader_on_camera": "是|否|不确定",
  "overlays": ["UP主解说字幕","歌词字幕","贴纸或表情包","装饰花纹或边框","文字标题卡","其他"],
  "other_works": "是|否|不确定",
  "other_works_desc": "",
  "form_guess": "reaction|混剪|解说|原片切条|不确定",
  "evidence_frames": [1, 2, 3, 4]
}
```

- `rights_content_ratio` 指原剧画面占被诉视频画面的比例。
- `overlays` 里**不要**算上平台水印、UP 主水印和弹幕。客户要求这几项不写，写了反而对当事人不利。
- `evidence_frames` 写这一行的判断依据了哪几帧。

**提示词要点：** 只描述手机屏幕里看得到的东西；看不清就写"不确定"；不要推测剧情，不要判断是否侵权。temperature=0。

## 4. 真值与指标

- **真值由 Owner 标注。** 每行输出一张 2×2 拼图（4 帧，宽 1280），路径写进 CSV。Owner 会看同样的拼图，按同一套枚举标注。
- **输出：**
  - `workspace/pilot/vlm/predictions.csv`：行 × 模型 × 字段；
  - 每个模型的平均耗时（秒/行）和峰值内存。
- **指标**（Owner 标注完后由 Owner 计算）：
  - 每个字段与 Owner 标注的一致率；
  - "凭空编造"的次数，即 overlays 或 other_works 里写了画面上并不存在的东西；
  - 耗时。
- **选型规则：** 优先看凭空编造次数，其次看一致率，最后看速度。
