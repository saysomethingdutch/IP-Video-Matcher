- 语音转写只有 1051–1127；其余行在核对页标"无 ASR"即可
- 分支：`pilot/wo-005-review`，从 `pilot/wo-001-ledger` 最新提交切出，再合并 `pilot/wo-003a-captions` 和 `pilot/wo-003b-asr`
- 代码目录：`pilot/review/`

## 0. 目的

这是所有者**唯一要用的界面**（D-005）：机器已经把每一行填好，所有者逐条"通过"或"修改"，最后导出 Excel。
- 页面要一眼能看懂；
- 同一 UP 主的一批视频可以一起通过；
- 所有修改都要留痕。

## 1. 形式

- **本地网页服务。** 只用 Python 标准库（`http.server` 加 JSON 接口）和原生 JS/CSS，不引入前端框架。
- 启动：`python -m pilot.review serve workspace/pilot/qsjx_e18`，然后在浏览器打开 `http://localhost:8765`。
- **只监听 127.0.0.1**，不对外开放。

## 2. 页面

**首页**
- 按录像分组，也可以切换成按 UP 主分组。
- 每行显示：行号、标题、状态（待核 / 已通过 / 已修改 / 待定）、黄标数、红标数。
- 顶部显示总进度。

**单行页**
- **左栏：证据**
  1. 关键帧：开始、每次跳转的前后、结束、截图。
  2. 播放时间轴：已播放段和跳过段用颜色区分，悬停可看录像秒。
  3. 字幕：原剧台词、UP 主文字、歌词分色显示，点开可看原剧集数和秒。
  4. 语音转写（有的话）。
  5. 集数证据和原告声称的对比结论。
- **右栏：比对表的各列**
  - 按比对表列顺序排列，预先填好机器的取值。
  - 每个值旁边能展开"依据"。
  - 黄标、红标醒目显示，并写明原因。
  - "比对意见"是可编辑的文本框：有草稿就填入草稿，没有就留空（WO-004c 完成后才有）。
- **按钮**：通过、修改后通过、待定。
- **快捷键**：J/K 上下一条，A 通过。
- **批量**：在 UP 主分组页可以"本组全部通过"。有红标的行不参与批量，必须单独确认。

**数据来源**
- 读取 WO-004b 的 `semantic/<row>.json` 或 `fields.csv`。
- 还没有的列，就从台账、字幕模块、ASR 的输出临时拼出来，并在页面上标"暂由底层模块推出"。

## 3. 留痕

- 每次操作追加一条记录到 `workspace/pilot/qsjx_e18/review/decisions.jsonl`：时间、行号、字段、原值、新值、动作。**只追加，不改写。**
- 另外导出 `corrections.jsonl`：所有者改过的"比对意见"和分类，作为以后批次的参照样例（D-007）。

## 4. Excel 导出

- 命令：`python -m pilot.review export workspace/pilot/qsjx_e18`
- **绝不修改原表**：复制 `/Volumes/Element/.../七时吉祥-比对总表 - 副本.xlsx`，在副本里填值。只写本案这 169 行（总编号 1051–1219）的产出列，**保留原有格式和其他内容**。
- 新增一张工作表"机器来源"，每个单元格一行：取值、来源、是否经所有者修改。
- 状态为"待定"的行，产出列写"待定"并标黄。
- 输出到 `workspace/pilot/qsjx_e18/export/七时吉祥-比对总表-机器填写-<日期>.xlsx`。

## 7. 补充（2026-09-25）

- **加粗**：比对意见中的 `**…**` 在页面上加粗显示；导出 Excel 时转成单元格内加粗（openpyxl `CellRichText`），星号本身不写进单元格。这是客户要求"体现转换性的重点部分需标粗"。
- **重复取证行**：WO-004b 会把非主行的意见和最后四格写成 `同序号XXXX，重复取证`。核对页上给这些行一个"跳到主行"的链接，批量通过时可以跟随主行一起通过。
- **画面拼图**：WO-004a-R2 会在 `workspace/pilot/vlm/full/<row>/` 生成拼图，放在左栏关键帧下面。
