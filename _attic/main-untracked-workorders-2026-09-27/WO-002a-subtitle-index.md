## 1. 目标

给一部剧的全部集数建立台词索引，每条记录是 `(集数, t_start, t_end, 原文, 归一化文本, 置信度, 标记)`。另外提供两个接口：
- **单句查询**：输入一句 OCR 或 ASR 文本，返回候选台词和相似度。
- **序列匹配**：输入一段带时间的文本序列，利用时间单调性消除歧义，输出 SourceLink 列表：`(输入行 → 集数, 原剧时间, 相似度, 置信度)`。

## 2. 输入（只读）

- 原剧：`real_test/EP01.ts` … `EP14.ts`（MPEG-TS、H.264、896×504、25fps）。
  - 《七时吉祥》全剧 38 集，EP15–38 **暂缺**，所有者会补充到同一目录。
  - 设计上要支持**增量加集**：新集数加入后只处理新集，不重建全部。
- 片头、广告、片尾的参考边界：`experiments/phase3a0/cases/source_boundaries.json`，这是一个保守规则：`content_start=140`，`content_end=duration-200`。**不要**用它把片头片尾删掉，只用来给这些区间里的台词打标记。

## 3. 技术要求

### 3.1 OCR
- 用 macOS Vision：`VNRecognizeTextRequest`，语言 `zh-Hans`，`accurate`，关闭语言校正。
- 为保持和 WO-001 独立，请**自带一份** Swift 小程序：`pilot/textindex/vision_ocr.swift`（约 30 行，参考审计附录 A）。以后在 WO-003 再合并成一份。
- 不要引入需要下载模型的 OCR。

### 3.2 抽帧
- 裁画面底部，高度从 0.78 到 1.0，以 **2 fps** 抽帧。
- 4 进程并行。
- 帧 OCR 完就删。内置盘只剩约 19 GB。

### 3.3 合并成台词条目
- 相邻帧的归一化文本相同，或编辑距离 ≤1，就视为同一句，合并出 `t_start` 和 `t_end`。
- 原文取出现次数最多、置信度最高的写法。

### 3.4 归一化
只保留汉字、数字、英文字母，去掉标点和空格。

### 3.5 标记
- `OPENING_ENDING`：在 ≥3 集里重复出现的句子，多为片头片尾曲歌词。
- `RECAP`：在相邻两集里都出现的句子，多为前情提要。
- `BOUNDARY_REGION`：落在参考边界之外的句子。
- `SHORT`：少于 4 个字的句子，信息量低。
- 标记只用来降权，不删除。

### 3.6 存储
- 用一个 SQLite 文件：`workspace/pilot/textindex/<work_id>/index.sqlite`。
- 另外生成 `stats.json`：每集条目数、带各类标记的比例、多集重复的比例、建索引耗时。

### 3.7 单句查询
- 用 2-gram 倒排索引召回候选，再用编辑距离（可以用 `difflib` 或 `rapidfuzz`）打分。
- 返回 Top-N 候选。一句话在多集都能匹配时，要如实全部返回。

### 3.8 序列匹配（关键）
- 输入：`[(t_query, text), ...]`，时间单调递增。
- 做法：
  1. 对每一行取候选；
  2. 用动态规划或类似方法，找一条"集数不变、原剧时间单调递增、间隔合理"的最佳链，允许链在集内或跨集跳转，但跳转要扣分。
- 输出每一行的归属：`LINKED`（带集数、时间、置信度）、`AMBIGUOUS`（列出候选）、`NO_MATCH`。
- **`NO_MATCH` 是正常结果**，代表 UP 主自己的字幕或旁白，不要强行匹配。

### 3.9 CLI
- 建索引：`python -m pilot.textindex build --episodes real_test --work qsjx`
- 查询：`python -m pilot.textindex query --work qsjx "现在要怎么办呀"`

### 3.10 环境
- `/opt/homebrew/bin/python3` 已经装好 numpy、PIL、pandas。rapidfuzz 没装，用标准库 `difflib` 即可。
- `swiftc` 与 `ffmpeg` 都可用。
- 不要下载模型。

### 3.11 测试
- 少量单元测试，覆盖合并、归一化和序列链。
- 回归测试用 §4 的样例，直接用文本做输入，不需要读录像。
